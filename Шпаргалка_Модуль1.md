## 1. Навигация в DevTools (`F12` или `Ctrl + Shift + I`)

В современных версиях Chrome, Edge и Яндекс Браузера элементы находятся здесь:
* **Вкладка `Elements`:** живое HTML-дерево и CSS-стили страницы. Правый клик по любому элементу на сайте → *«Просмотреть код»* открывает нужный тег прямо здесь.
* **Вкладка `Console`:** ошибки JS и строка, куда можно вводить команды (например, `document.cookie` или `localStorage`).
* **Вкладка `Network` (Сеть):**
  * **`Keep log`** (в старых версиях называется **`Preserve log`**) — сохраняет запросы даже после перезагрузки или `302`-редиректа.
  * **`Disable cache`** — отключает кэш, пока открыт DevTools (чтобы поймать `304`, эту галочку нужно **снять**!).
  * **Фильтры `Doc` / `Fetch/XHR`:** отсекают лишние картинки/стили и оставляют только страницы и API-запросы.
  * **Клик по строке в списке `Name`** открывает справа:
    * **`Headers`** → `General` (URL, метод, статус), `Response Headers` (заголовки от сервера), `Request Headers` (заголовки от браузера, включая `Cookie`).
    * **`Payload`** → отправленные URL-параметры (`Query String`) или JSON-тело (`Request Payload`).
    * **`Preview` / `Response`** → красивый JSON или сырой текст ответа сервера.
* **Вкладка `Application`:** если не видна на верхней панели, нажми **`>>`** справа от `Performance`. Внутри слева: **`Cookies`** (видны даже `HttpOnly` куки!) и **`Local Storage`**.

## 2. Шпаргалка по HTTP-методам и статус-кодам

| Метод | Для чего нужен | Где лежат данные | Типичный статус |
| :--- | :--- | :--- | :--- |
| **`GET`** | Получить страницу или найти данные | В адресной строке (`?q=cookie`) | `200 OK`, `304 Not Modified` |
| **`POST`** | Создать запись, войти в аккаунт, отправить форму | В теле запроса (`Body / Payload`) | `200 OK`, `201 Created` |
| **`PUT` / `PATCH`** | Обновить существующую запись по ID | В теле запроса + ID в URL | `200 OK` |
| **`DELETE`** | Удалить ресурс по ID | Обычно в URL (`/notes/3`) | `200 OK`, `204 No Content` |

### Главные статус-коды:
* **`200 OK`** — успех, данные получены.
* **`201 Created`** — новый объект создан (обычно после `POST`).
* **`302 Found`** — временный редирект (смотри заголовок `Location` в ответе).
* **`304 Not Modified`** — ресурс не изменился (проверка по `ETag`), браузер взял из кэша.
* **`400 Bad Request`** — некорректный ввод или ошибка формата JSON.
* **`401 Unauthorized`** — пользователь не вошёл в аккаунт.
* **`403 Forbidden`** — вошёл (или доступ закрыт), но **не хватает прав** (например, роль `student` вместо `mentor`) или подпись JWT не совпала.
* **`404 Not Found`** — адрес или объект не найден.
* **`429 Too Many Requests`** — слишком частые запросы (сработал Rate Limiting; смотри заголовок `Retry-After`).
* **`500 Internal Server Error`** — ошибка в коде сервера.

## 3. Где хранятся данные авторизации: сравнение

| Механизм | Видит ли JavaScript (`document.cookie` / JS)? | Где посмотреть в `F12` | Главный риск и защита |
| :--- | :--- | :--- | :--- |
| **Обычная Cookie** (`public_user`) | **Да** | `Application → Cookies` и `Console` | Может быть прочитана при XSS. Не хранить там секреты! |
| **Cookie с `HttpOnly`** (`lab_session`) | **Нет** (защищена!) | Только `Application → Cookies` (колонка `HttpOnly ✓`) и `Network → Request Headers` | Отправляется браузером автоматически → защищать флагом `SameSite=Lax/Strict` от CSRF. |
| **JWT в `localStorage`** (`weblab_jwt`) | **Да** (полный доступ из JS) | `Application → Local Storage` | Payload читается в Base64 кем угодно! Не хранить там пароли; изменять нельзя — сервер проверяет криптоподпись `Signature`. |

## 4. Пошаговый маршрут прохождения тренажёра (30–40 минут)

1. **Старт:** Дважды кликни по `Запустить_Тренажер.bat` — откроется `http://127.0.0.1:8080` (или соседний свободный порт). Нажми **`F12`**, перейди в **`Network`**, включи **`Keep log`** и фильтр **`Fetch/XHR`**.
2. **Шаг 1 (Вкладка «1. HTTP-методы»):**
   - Введи слово в поиск, поменяй `X-Student-Tag` и нажми **Отправить GET-запрос**. Найди в `Network` запрос `search?...` и посмотри свои параметры и заголовок в `Headers` / `Payload`.
   - Создай заметку (**POST** → статус `201`), измени её (**PUT** → `200`) и удали (**DELETE** → `200`).
3. **Шаг 2 (Вкладка «2. Статус-коды»):**
   - Прокликай `200`, `201`, `400`, `401`, `403`, `404`, `500`.
   - Сними галочку `Disable cache` и нажми **`304 (Кэш ETag)` два раза** — на 2-й раз увидишь настоящий статус `304` и заголовки `ETag` / `If-None-Match`.
   - Нажми **`302 (Редирект страницы)`** при включённом `Keep log` — проверь, как сохранился запрос `302-page` вверху списка.
   - Нажми **`429 Rate Limit`** 4 раза подряд — поймай защиту `429` и посмотри заголовок `Retry-After`.
4. **Шаг 3 (Вкладка «3. Cookies, Сессии и JWT»):**
   - Подставь `student / 1234` и нажми **Войти**.
   - Нажми **Прочитать `document.cookie`**: увидишь только `public_user`. Открой `Application → Cookies` — увидишь и `public_user`, и **`lab_session` (с галочкой `HttpOnly`)**!
   - Попробуй зайти в **Панель наставника** → получишь `403 Forbidden`.
   - Внизу нажми **Подменить роль на "mentor" в Payload** и отправь JWT на сервер → сервер отклонит подделку (`403`), потому что без секретного ключа сервера подпись не сходится!
   - Теперь войди под `mentor / admin123` и снова зайди в **Панель наставника** → получишь `200 OK` и флаг!
5. **Шаг 4 (Вкладка «4. Клиент vs Сервер»):**
   - В режиме **Наивный сервер** подмени цену на `1 руб.` — сумма станет `1 руб.` (ошибка бизнес-логики!).
   - Переключись на **Защищённый сервер** и снова попробуй отправить `1 руб.` или количество `-2` — посмотри, как сервер отбивает подмену.
6. **Шаг 5 (Вкладка «5. Квесты F12»):**
   - Закрой все **6 квестов** до результата `6 / 6`!
